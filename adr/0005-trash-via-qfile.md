# Перемещение файлов в корзину через QFile::moveToTrash

## Контекст и постановка задачи

Действием по умолчанию при очистке дубликатов является перемещение отмеченных файлов в корзину Windows (REQ-FUNC-016, REQ-SEC-003). Если корзина на диске недоступна (например, на флешке), пользователь должен получить предупреждение до выполнения действия (REQ-FUNC-017). Требуется выбрать способ работы с корзиной Windows.

## Драйверы решения

* Надёжное перемещение в корзину Windows 10/11 с возможностью восстановления.
* Минимум платформозависимого WinAPI-кода.
* Изоляция системного вызова в отдельном адаптере (`TrashAdapter`).

## Рассмотренные варианты

* `QFile::moveToTrash()` (встроенный метод Qt 6) + проверка типа диска через Windows API для предупреждения до удаления
* Прямой вызов Windows Shell API (`IFileOperation` / `SHFileOperationW`)

## Итог решения

Выбранный вариант: «`QFile::moveToTrash()` с проверкой типа диска в `TrashAdapter`», потому что Qt 6 уже реализует безопасный вызов Shell API внутри `moveToTrash()`, а короткая проверка `GetDriveTypeW` позволяет заранее предупредить пользователя о съёмном диске без корзины.

### Последствия

* Хорошо, потому что минимум кода на WinAPI и меньше риск ошибок с указателями и COM-инициализацией.
* Хорошо, потому что логика сосредоточена в `TrashAdapter` — при необходимости реализацию легко заменить.
* Плохо, потому что если пользователь вручную отключил корзину на локальном диске в свойствах Windows, это обнаружится только при неудаче `moveToTrash()`, о чём будет показано сообщение.

### Подтверждение

Ручная проверка перемещения файлов в корзину на локальном диске и проверка предупреждения на съёмном накопителе (REQ-FUNC-016, REQ-FUNC-017).

## Плюсы и минусы вариантов

### QFile::moveToTrash()

* Хорошо, потому что встроен в Qt 6, поддерживает Unicode-пути и возвращает булев результат.
* Плохо, потому что сам метод не проверяет доступность корзины заранее — дополняется проверкой типа диска.

### Прямой вызов IFileOperation / SHFileOperationW

* Хорошо, потому что полный контроль над флагами оболочки Windows.
* Плохо, потому что требует инициализации COM, аккуратного освобождения ресурсов и усложняет код.

## Дополнительная информация

Затрагивает требования: REQ-FUNC-016, REQ-FUNC-017, REQ-SEC-003. Элемент SDD: `002-composition`, `006-interaction-cleanup` (`TrashAdapter`, `ActionService`).
