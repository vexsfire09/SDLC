# Трёхэтапное сравнение файлов с хэшем SHA-256 (MD5 по выбору)

## Контекст и постановка задачи

Приложение должно находить дубликаты только по полному совпадению содержимого независимо от имени и даты (REQ-FUNC-007), при этом укладываться в 3 минуты на 10 000 файлов общим объёмом 10 ГБ (REQ-PERF-002) и позволять выбрать в настройках SHA-256 или MD5 (REQ-FUNC-025). Как организовать сравнение, чтобы не читать лишние файлы целиком и не допускать ложных совпадений?

## Драйверы решения

* Точность: отсутствие ложных дубликатов, иначе пользователь может удалить нужный файл.
* Скорость поиска на больших объёмах данных (REQ-PERF-002).
* Умеренное потребление памяти: файлы не загружаются в память целиком (REQ-PERF-004).
* Возможность переиспользовать алгоритм в сравнении двух папок (REQ-FUNC-023).

## Рассмотренные варианты

* Трёхэтапное сравнение: размер → хэш первых 64 КБ → полный хэш SHA-256 (MD5 по выбору в настройках)
* Полный хэш всех файлов сразу
* Попарное побайтовое сравнение файлов одинакового размера

## Итог решения

Выбранный вариант: «Трёхэтапное сравнение: размер → хэш первых 64 КБ → полный хэш SHA-256 (MD5 по выбору)», потому что первые два этапа дёшево отсеивают почти все уникальные файлы, а SHA-256 по умолчанию гарантирует отсутствие случайных коллизий.

### Последствия

* Хорошо, потому что большинство файлов отсеивается уже по размеру и вообще не читается с диска.
* Хорошо, потому что один и тот же конвейер используется для поиска дубликатов и сравнения двух папок.
* Плохо, потому что для настоящих дубликатов файл открывается дважды (для 64 КБ и для полного хэша), что незначительно при чтении блоками по 1 МБ.

### Подтверждение

Автоматический тест на наборе файлов с одинаковыми и разными именами, а также замер времени на тестовом наборе (REQ-FUNC-007, REQ-PERF-002).

## Плюсы и минусы вариантов

### Трёхэтапное сравнение (размер → 64 КБ → полный хэш)

* Хорошо, потому что минимальный объём чтения с диска.
* Хорошо, потому что использует встроенный `QCryptographicHash` без внешних библиотек.
* Нейтрально, потому что выбор MD5 доступен в настройках для пользователей, которым нужна максимальная скорость на старом ПК.

### Полный хэш всех файлов сразу

* Хорошо, потому что максимально простая логика.
* Плохо, потому что читает с диска все 10 ГБ, даже файлы уникального размера — не укладывается в REQ-PERF-002.

### Попарное побайтовое сравнение

* Хорошо, потому что исключает коллизии хэшей.
* Плохо, потому что при большом числе копий одинакового размера сложность квадратичная и нельзя кэшировать результат (REQ-FUNC-022).

## Дополнительная информация

Затрагивает требования: REQ-FUNC-007, REQ-FUNC-023, REQ-FUNC-025, REQ-PERF-002, REQ-PERF-004. Элемент SDD: `007-algorithm` (`DuplicateFinder`, `HashService`).
